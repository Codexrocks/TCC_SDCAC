**Data:** 03/09/2026 · **Participantes:** Davi + Claude

## O que foi pedido

> O nome padrão do arquivo do GitBook deve ser `gitbook-docs.yaml`. Sou o
> proprietário da organização — me ajude a configurar tudo que for preciso.
> Quero criar regras e padrões a serem seguidos em commit, pull, push, merge e
> docs, assim como os relatórios, e para que você não se perca e tenha como
> regra. Como é uma organização, não consigo colocar regras na branch porque
> estou no plano grátis.

## Decisões tomadas

| Decisão | Motivo |
|---|---|
| Tornar o repositório público | No plano gratuito, regra de branch em repositório **privado** de organização é paga; em repositório **público** é gratuita. Sem isso não há trava real contra push na `main`. |
| Manter o e-mail do líder publicado | Escolha do Davi, ciente de que o site do GitBook é público. |
| Regras do assistente em `CLAUDE.md` | É o arquivo que o Claude lê automaticamente em toda sessão — a regra passa a valer sem ninguém precisar lembrar de repetir. |
| Validação como script, não só como workflow | O mesmo `scripts/validar.py` roda no terminal antes do commit e no CI. Uma fonte só de regra, sem duplicar lógica em YAML. |
| `gitbook-docs.yaml` em vez de `.gitbook.yaml` | Nome indicado pela interface do Git Sync. O arquivo precisa bater exatamente com o campo *Config file*. |
| Erros bloqueiam, avisos não | Nome de branch e formato de commit são objetivos e viram erro. Assunto longo demais é aviso — não vale travar entrega por isso. |
