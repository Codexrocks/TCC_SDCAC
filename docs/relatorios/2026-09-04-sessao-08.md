# 2026-09-04 — Sessão 08: um site do GitBook tem uma branch só

**Data:** 04/09/2026 · **Participantes:** Davi + Claude

## O que foi pedido

> O GitBook deve ficar na `main`, `artigo` ou `documentacao`? E como crio o
> espaço do artigo no GitBook?

E, depois da primeira resposta:

> Já troquei a branch do espaço artigo, agora é só esperar aprovar o PR.

## O que foi feito

- Conferido o Git Sync dos dois espaços pela API do GitBook
- Encontrada uma configuração errada, que descartaria o texto do artigo
- Depois da troca feita pelo Davi, conferido de novo — e descoberto que **os
  dois espaços andam juntos**, porque o Git Sync é do site, não do espaço
- Confirmado na documentação oficial do GitBook
- `docs/configuracao.md` corrigido: a tabela de duas branches saiu, porque
  documentava algo impossível
- Corrigida a numeração duplicada das seções (havia duas `## 6`)

## A resposta à pergunta

O espaço **Artigo já existia** — o GitBook cria os espaços sozinho a partir do
`gitbook-docs.yaml`. Não havia espaço para criar.

E nenhum dos dois aponta para a `main`: a `main` é protegida, e o Git Sync
empurra commit direto na branch que receber.

## O achado principal

**Um site do GitBook sincroniza com uma branch só.** Documentação oficial:

> Use site-wide Git Sync to sync multiple spaces from **one repository and
> branch**. Map each space to its own directory in `gitbook-docs.yaml`.

O `gitbook-docs.yaml` separa os espaços por **diretório**, nunca por branch. Os
dois espaços compartilham o mesmo `parentInstallationId` — trocar a branch em um
troca no outro.

Foi o que aconteceu ao apontar o Artigo para `gitbook/docs/artigo`: a
Documentação foi junto e exportou todo o `docs/` reformatado para dentro da
branch do artigo — 18 arquivos, incluindo os comentários do `gitbook-docs.yaml`
apagados de novo e o `docs/relatorios/relatorios.md` recriado.

**O que segurou o estrago foi a trava do `gitbook-sync.yml`**, que recusa levar
para a `main` qualquer arquivo fora de `artigo/`. Os três runs falharam e nenhum
Pull Request foi aberto. A trava escrita numa sessão anterior pegou exatamente o
caso para o qual foi escrita.

## Decisões tomadas

| Decisão | Motivo |
|---|---|
| Não mexer no Git Sync pela API | O servidor MCP do GitBook diz que a ligação é só pela interface. Forçar por uma rota genérica arriscaria derrubar a sincronização inteira. |
| Reconfirmar na documentação antes de afirmar | O achado derruba o desenho de duas branches, que está na `main`. Afirmar isso errado custaria mais que a checagem. |
| Não redesenhar o `gitbook-sync.yml` nesta sessão | Mexer em `.github/` exige duas aprovações e é decisão de escopo do Davi, não da IA. O relatório apresenta as opções. |
| Tirar a tabela de duas branches em vez de só corrigir a nota | A tabela era o erro: dava instrução de configurar algo que o GitBook não permite. |
