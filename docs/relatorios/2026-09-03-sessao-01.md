## O que foi pedido

> Criar a primeira publicação do repositório, que está vazio. Algo muito
> resumido e simples: o GitHub é o versionamento do protótipo (que vem mais
> adiante) e o GitBook auxilia na documentação do TCC. Definir o que cada
> pessoa vai fazer — Davi, Yasmin e Filipe. Estabelecer um processo para
> encaminhar tudo ao GitHub e ao GitBook, configurar o GitBook para o Claude
> ter acesso, e criar um workflow para o Claude poder agir quando solicitado.
> Regras de push, commit, merge e branch. O mais minimalista possível, para as
> ideias não se perderem. E relatórios constantes das ações e das conversas.

Anexos analisados: `OrientaçõesTCC_2026_2.pdf` (professor) e
`Plano Executivo e Manual Técnico do TCC.pdf` (equipe).

## Decisões tomadas

| Decisão | Motivo |
|---|---|
| Documentação vive em `docs/` no GitHub, GitBook espelha | Uma fonte da verdade só; evita documento solto em Drive/WhatsApp |
| `main` protegida, tudo por Pull Request com 1 aprovação | Equipe de 3 — 1 revisor é suficiente sem virar burocracia |
| Squash and merge | Histórico da `main` limpo: 1 PR = 1 commit |
| Commits em português com prefixo `docs:`/`feat:`/`fix:`/`chore:` | Padrão reconhecível sem exigir estudo de convenção |
| Pastas de código (`backend/`, `detection/`…) só na S6 | Nesta etapa o protótipo ainda não começou; pastas vazias viram ruído |
| Davi = Pessoa 1, Yasmin = Pessoa 2, Filipe = Pessoa 3 | Ordem informada pelo Davi na conversa |

## Observações sobre o estado do repositório

- O repositório é **privado**. O e-mail do líder em `docs/entregas/tarefa-01.md`
  não está exposto publicamente. Se o Space do GitBook for publicado como
  público, reavaliar.
- O repositório pertence a uma **organização** (`Codexrocks`) — a autorização do
  GitBook e da GitHub App do Claude precisa ser feita no nível da organização.
- Como o repositório foi criado vazio, o GitHub adotou a primeira branch enviada
  como padrão. A `main` já existe com o mesmo conteúdo, mas ainda **não** é a
  branch padrão.
