## O erro do GitBook — causa

Na sessão anterior eu renomeei `.gitbook.yaml` para `gitbook-docs.yaml` tratando
os dois como o mesmo arquivo com nomes diferentes. **São arquivos distintos, com
schemas distintos:**

| Arquivo | Onde fica | Chave raiz |
|---|---|---|
| `gitbook-docs.yaml` | raiz do repositório | `site` |
| `.gitbook.yaml` | dentro da pasta do espaço | `root` / `structure` |

O arquivo renomeado tinha `root:` e `structure:` — o conteúdo do segundo com o
nome do primeiro. Daí o GitBook cobrar a chave `site`.

Também estava errada a instrução de preencher **Project directory** com `docs`.
O `gitbook-docs.yaml` fica na raiz, então esse campo tem de ficar **vazio**.

## Decisões tomadas

| Decisão | Motivo |
|---|---|
| Manter os dois arquivos, cada um no seu lugar | É o formato documentado pelo GitBook. `gitbook-docs.yaml` mapeia o site; `.gitbook.yaml` configura o espaço. |
| Escrever o `gitbook-docs.yaml` à mão em vez de deixar o GitBook gerar | O GitBook só gera o arquivo depois que a sincronização funciona — e ela não funciona enquanto o arquivo estiver inválido. |
| Chave do espaço fixada como `documentacao` | O GitBook identifica o espaço pela chave. Trocar depois faz ele criar outro espaço do zero e abandonar o antigo. |
| Workflow aceitando os dois tipos de credencial | `claude setup-token` usa a assinatura Pro/Max que o Davi já tem; a chave de API exigiria créditos numa conta separada. |
| Guia de configuração como página própria | `processo.md` explica o fluxo; `configuracao.md` resolve o "não sei onde clicar". Misturar os dois deixa as duas coisas piores. |
