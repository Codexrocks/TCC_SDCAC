## A saída, que não é criar site

Documentação do GitBook, em `enabling-github-sync.md`:

> **Exclude a space from site-wide Git Sync** — In the site's Git Sync content
> mapping, click the remove icon next to the space you want to exclude. You can
> then configure Git Sync from that space.
>
> * Select an **independent repository and branch** to configure Space Git Sync.

Com isso, cada espaço fica no regime que o `gitbook-sync.yml` já pressupõe —
**sem mudar uma linha do workflow**:

Sobre o laço de restauração: a lição não é "conferir a branch" — é que um
comando destrutivo em laço não pode depender de um comando anterior ter dado
certo. O `checkout -B` falhou e imprimiu o erro, e ainda assim o laço seguinte
rodou. Um `set -e`, ou conferir a branch antes de restaurar, teria parado ali.

Sobre o primeiro: o padrão que se repete é eu concluir "não dá" a partir de um
caminho só. Nas sessões 03 e 08 aconteceu o mesmo — afirmei limitação do
GitBook sem esgotar a documentação. Vale como sinal para quem revisa: minhas
afirmações de impossibilidade merecem mais desconfiança que as de fato.
