## Decisões tomadas

| Decisão | Motivo |
|---|---|
| **A ordem de merge passou a ter o #99 antes do #97** | As dez sementes incluem a C3, que só existe com o código do #99. Na ordem anterior o #97 registraria um resultado que o próprio código dele não produz |
| **A agregação vai para `evaluator/`, não para `scripts/`** | `scripts/` é arquivo protegido e exigiria 24 h. Mas o motivo principal é outro: agregar execuções é trabalho do avaliador, não ferramenta de repositório — e assim o número do artigo se reproduz com um comando documentado |
| **Wilcoxon exato por programação dinâmica, em vez de SciPy** | O CI instala `pytest pyyaml fastapi httpx`. Enumerar 2^n seria lento a partir de quinze sementes; a contagem por programação dinâmica é exata e barata em qualquer n do desenho |
| **A identidade de uma semente é o nome da pasta, não o `run_id`** | Descobri na marra: as dez têm `run_id` igual a 1, porque cada semente tem seu próprio conjunto gerado começando em `run_001`. A guarda de duplicata que escrevi recusou as dez e o motivo era este |
| **O resumo por execução é gravado pelo executor, não calculado na leitura** | É o único ponto do sistema que já percorre os eventos em ordem. Calcular na leitura é o que custava 140 s |
| **Os brutos das sementes não entram no repositório** | 37 GB. Regerar é determinístico, e a verificação disso está registrada: a semente 42 rodada duas vezes deu `metricas.json` idêntico em todos os números |
