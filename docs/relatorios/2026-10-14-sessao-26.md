## O que foi respondido / feito

### A verificação de coerência passou — e foi isso que escondeu o problema

Na `main`, tudo verde: `validar.py` OK, 185 testes, e o
`scripts/quadro.py --conferir` respondendo **"Quadro coerente"**.

Só que o retrato gravado era de **29/09**, quinze dias antes. O `--conferir`
compara conteúdo contra conteúdo **usando a data gravada na própria página** —
desenho deliberado, para o check não falhar todo dia só porque o calendário
andou. O efeito colateral é que ele não tem como perceber que a página inteira
está velha.

A página pública seguia anunciando a M2 como *"vence em 2 dias"* — ela venceu em
01/10, treze dias antes — e a S5 como *em curso*, quando o cronograma já estava
na S7.

### O workflow que devia impedir isso falhava desde 06/10

**Oito execuções seguidas com falha**, de 06/10 a 13/10. O passo que quebrava era
o *"Preparar a branch do quadro"*, escrito por mim na sessão 17.

A causa é estrutural, não descuido. O repositório usa **squash merge**: o commit
que a branch fixa `claude/chore/quadro-diario` empurrou em 29/09 entrou na `main`
como outro commit, com outro SHA. Depois os PRs #62 e #63 mexeram nas mesmas três
páginas geradas. A partir dali o `git merge origin/main` conflita em
`docs/quadro.md` **todas as vezes** — reproduzido localmente nesta sessão.

E o passo para, porque eu escrevi "conflito: pare e relate". Ele para
corretamente, e para **todos os dias, para sempre**, sem ninguém ler a falha:
workflow agendado que falha não aparece em lugar nenhum.

### O conserto

Branch longa e squash merge não se reconciliam. Como **tudo na branch é gerado**,
não há nada nela que valha preservar — a saída é nascer da `main` a cada dia, em
vez de tentar alcançá-la:

| Situação | O que o workflow faz |
|---|---|
| Há PR do quadro aberto | Continua na branch dele e acrescenta commit — não acumula um PR por dia. Conflito aqui é sinal de verdade |
| Não há PR aberto | Cria `claude/chore/quadro-AAAA-MM-DD` **a partir da `main`** |

Nada disso usa `git push --force`, que a seção 4 proíbe.

O corpo do PR saiu de dentro do YAML e virou arquivo —
`.github/quadro-corpo-de-pr.md`. Deixa de depender de indentação de *heredoc*,
que é a classe de erro que já quebrou este mesmo arquivo uma vez, e passa a ser
revisável como texto.

### O que deliberadamente NÃO foi feito

**Não abri PR atualizando o quadro.** Seria um sexto PR tocando `docs/quadro.md`,
`docs/cronograma.md` e `docs/decisoes.md` — exatamente os arquivos que o #64, o
#67 e o #68 já alteram. Pioraria o conflito em vez de resolver. Os PRs abertos já
regeneram o quadro para 13/10, e o workflow consertado cobre os dias seguintes.

## Decisões tomadas

| Decisão | Motivo |
|---|---|
| Branch do dia, não branch fixa | Squash merge torna a branch longa irreconciliável com a `main`. Tudo nela é gerado: não há o que preservar |
| Continuar na branch quando há PR aberto | Evita um PR por dia. E aí um conflito significa que alguém mexeu nas páginas geradas com o PR aberto — vale parar |
| Corpo do PR vira arquivo | Tira do YAML a única parte que dependia de indentação de *heredoc*. Já quebrou este arquivo uma vez |
| Não abrir PR de atualização do quadro | Seria o sexto PR nos mesmos arquivos gerados. O conflito que ele criaria é maior que o problema que resolveria |
| Não escrever relatório para #65 a #68 | Não foram minhas sessões. Escrever o registro de trabalho que não vi é inventar a prova — ver seção 3 |
